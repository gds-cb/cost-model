# 第二轮：费率预设 + 材料价格批量导入

> 目标：让「不会调」和「懒得调」的人也能用起来。
> 起因：工具的设计前提是「客户自己调参数」，但**客户得会调、愿意调**，否则这个前提不成立。

## 为什么做这两件事

原材料价格是公开商品（我的钢铁、上海有色网都能查），所以「保持价格新鲜」**不该由工具作者承担**。
但直接把一堆输入框丢给用户也不行——研发人员不知道该填什么，小供应商老板懒得填。

于是分成两条使用路径：

| | 会调的人 | 不会调 / 懒得调的人 |
|---|---|---|
| 费率 | 直接改管理费率、利润率、模具单价 | 选一个**费率预设**档位 |
| 材料价 | 逐条编辑材料库 | **批量导入价**：粘贴一张价格表 |

## 新增能力 1：费率预设（地区 × 自动化水平）

| 档位 | 人工费率 | 设备费率系数 | 模具价格系数 | 下料利用率 |
|---|---|---|---|---|
| 华东 · 高自动化 | 38 元/h | ×1.20 | ×1.15 | 78% |
| 华东 · 通用（基准） | 35 元/h | ×1.00 | ×1.00 | 75% |
| 华南 · 通用 | 38 元/h | ×1.00 | ×1.05 | 75% |
| 华北 · 通用 | 32 元/h | ×0.95 | ×0.95 | 73% |
| 内陆 · 低成本 | 26 元/h | ×0.80 | ×0.80 | 70% |

**三条设计约束（很重要）：**

1. **预设不改参数库** —— 材料、设备、判例都是客户自己维护的，预设只改费率类参数
2. **设备费率用「系数」不用绝对值** —— 既体现地区差异，又不破坏客户维护的设备表
3. **预设不掺管理费率与利润率** —— 这是被测试逼出来的修正，见下

### 一个被测试抓出来的设计错误

第一版预设里我给每档都设了管理费率和利润率（高自动化档 10%/8%，内陆档 15%/12%）。
端到端测试立刻报错：

```
✗ 切到「华东·高自动化」后完全成本上升
    47.34 → 46.46
```

**设备与模具费率高 20%/15%，但管理费率与利润率同时下调，净效果是总成本反而更低。**

这在经济上说得通（大厂有规模效应），但作为**用户界面**是灾难：
用户选「高自动化」，成本却降了，他会怀疑工具坏了。

**修正**：预设只管「制造成本驱动因子」（人工、设备、模具、材料利用率）。
管理费率与利润率是**商务决策**（这家公司想赚多少），不是地区属性。

现在各档位的完全成本严格单调：内陆 < 华北 < 华东通用 < 华南 < 华东高自动化。
这条约束已写成单元测试（`tools/test-db.js`），防止以后再被改坏。

## 新增能力 2：材料价格批量导入

- **粘贴即导入**：一行一条 `牌号,单价`，第三列可写数据来源
- **8 种分隔符**：中英文逗号、制表符（从 Excel 直接复制）、分号、竖线、单/多空格
- **模糊匹配**：大小写、全角/半角、前后空格都不影响匹配
- **表头与注释自动跳过**：`牌号,单价` / `# 注释` / `// 注释` 都不会被当成数据
- **导入前预览**：逐条显示「原价 → 新价 → 变化幅度」，未匹配项和无法解析的行单独列出
- **自动记录来源与日期**：写入 `source` 与 `updatedAt`，一眼能看出哪条数据是三个月前的
- **一键下载模板**：含当前所有牌号，客户改完数字直接粘回来

**这一条把「参数会过期」从工具作者的长期义务，变成了客户 3 分钟的自助操作。**

## 二、⚠️ 必须先知道的三件事

### 1. 页面必须通过 HTTP 访问（或直接双击落地页）

子页面通过相对路径加载 `../assets/*.js`。通过 HTTP 访问最稳妥：

```bash
npx serve .          # 然后打开 http://localhost:3000
```

直接双击 `injection/index.html` 在 Chrome/Edge 下脚本仍能加载，但部分浏览器在
`file://` 下会禁用 `localStorage`，导致参数库无法保存。**建议统一走 HTTP。**

### 2. 参数数据会自动迁移，但请先做一次备份

首次打开新版页面时，`CostDB.migrateLegacy()` 会把旧版 `localStorage` 里的
材料/表面处理/设备/案例库迁移到新的参数库（幂等，只执行一次）。

**保险做法**：升级前先打开旧版页面，把材料价格抄下来或截图；升级后核对一遍。
迁移不会删除旧键，所以数据仍在浏览器里，不会丢。

### 3. 「重置」按钮的行为变了（这是修复，不是 bug）

- **旧版**：`localStorage.clear()` —— 会把**两个工具**的数据一起清空。
- **新版**：只恢复本页的默认参数，不影响另一个工具的数据。

## 五、如何验证

```bash
# 1. 引擎算得对不对（74 项，纯 Node，无需依赖）
node tools/test-engine.js

# 2. 代码与页面是否对得上（id 引用 / CDN 残留 / 资源存在性）
node tools/check-dom.js

# 3. 页面真的能跑起来吗（45 项，需要 jsdom）
set NODE_PATH=%TEMP%\cost-domtest\node_modules
node tools/smoke-dom.js
```

三套测试覆盖的关键断言包括：
- 冲压件模具重量 = 6300kg（**不是** 8300kg，反证 bug 3 已修）
- 完全成本与独立手算一致（材料 + 加工 + 焊接 + 模具 + 物流，×1.232）
- 355T 需求映射到 400T 后结果与原 400T **完全一致**（反证设备匹配是按「不小于」而非精确相等）
- 连续调用 `calculate()` 三次不产生历史记录（反证 bug 5 已修）
- 费率清零后「含税报价 = 完全成本」
- 非法壁厚给出校验提示且不产生 NaN
